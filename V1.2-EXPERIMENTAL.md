# Keural Nova v1.2 (experimental) — training, evaluation, and release

This documents the **v1.2 experimental run**: goal, data, recipe, the full
train→merge→gate→publish pipeline, results, and how to reproduce it. It builds on the v1
pipeline (`README.md`, `VERIFIED-FACTS.md`) and the v2 dataset/plan
(`V2-DATASET-PREP.md`, `V2-TRAINING-PLAN.md`).

**Published model:** https://huggingface.co/mkd-hossain/Keural-Nova-v1.2-experimental (Apache-2.0)

---

## 1. Goal

Improve **Korean**, **tool-calling (incl. long context up to 32k)**, and **code** while holding
general capability flat vs base — a *skill/style-focused* fine-tune, not knowledge injection.

## 2. Data (~162k examples)

- **v2 clean set** (`data/processed_v2/`, 144,812 rows): Korean conversation/instruction, clean
  **AST-validated** code, English replay, MCQ (KMMLU/MMLU *train/aux* splits — **test excluded**),
  math, long-form, identity — all de-contaminated. See `V2-DATASET-PREP.md`.
- **Tool-calling slice** (~17,337 rows, built by [`scripts/build_tooluse_slice.py`](scripts/build_tooluse_slice.py)):
  single-turn, multi-turn (call→result→answer), negative (no-call), and **long-context up to 32k**.
  Sources: `glaiveai/glaive-function-calling-v2` + `NousResearch/hermes-function-calling-v1`
  (both **Apache-2.0**), converted to ms-swift's native agent schema (Qwen XML tool calls), plus a
  small hand-built Korean tool-use set. Schema details in [`docs/tooluse-schema.md`](docs/tooluse-schema.md).
- **Identity slice** (optional, `scripts/build_identity_dataset.py`): Keural/MKD identity, ko+en
  (not included in the shipped v1.2 mix — too diluted at 200 rows without upweighting).

## 3. Recipe (preservation-tuned) — `configs/train_v12.yaml`

Fresh from **`Qwen/Qwen3.6-35B-A3B`** (never from v1.0/v1.1). LoRA via **ms-swift 4.4.0**:

| Setting | Value | vs v1.0 |
|---|---|---|
| rank / α / dropout | **16 / 32 / 0.0** | was 32/64/0.0 — lower rank = less forgetting |
| learning rate | **5e-5** | was 1e-4 |
| epochs | **1** | was 2 |
| targeting | attention + Gated-DeltaNet linear-attn + shared experts + all routed experts (`target_parameters`) | same |
| router / gates | **frozen** | same |
| max_length | **32768** (admits the long tool-use slice) | was 8192 |
| precision / parallel | bf16, DeepSpeed ZeRO-2, 2× H200 | same |

Runtime: 1 epoch = 5,068 steps, ~27h. `attn_impl: sdpa` (H200 dispatches to
FlashAttention/mem-efficient kernels — no separate flash-attn needed).

## 4. Pipeline (train → publish)

1. **Train** — `python scripts/train.py --config configs/train_v12.yaml` (pre-training
   LoRA-targeting gate must pass: router/embed/lm_head frozen, experts targeted).
2. **Merge** — `python scripts/merge_lora.py --config configs/publish_v12.yaml --checkpoint outputs/v12/kept/checkpoint-5068`
   (CPU, MTP re-injection, integrity-checked).
3. **Non-thinking template fix** — the merge copies aux files from *base* (thinking-default);
   re-apply the fix so tool-calling doesn't loop: set the template default to non-thinking
   (`enable_thinking is not defined or enable_thinking is false`) in `chat_template.jinja` **and**
   `tokenizer_config.json`.
4. **Gate** — tool-calling ([`scripts/gate_toolcall_v12.py`](scripts/gate_toolcall_v12.py)) +
   benchmarks (`scripts/run_eval.py --tag v12`) → `scripts/compare_evals.py --baseline base --candidate v12`.
5. **Publish** — model card + upload to HF.

*(A base+adapter "proxy gate" was attempted to avoid full merges but failed on a PEFT/transformers
version bug loading `target_parameters` adapters — fell back to the tested merge path.)*

## 5. Results

Same harness (lm-eval, vLLM, seed 42) across base and every Keural Nova version.

| Benchmark | Base | v1.0 | v1.1 | **v1.2** |
|---|---:|---:|---:|---:|
| **KoBEST** (ko) | 62.88 | 68.82 | 67.29 | **70.03** |
| **KMMLU** (ko) | 64.46 | 62.52 | 62.38 | **63.50** |
| HAE-RAE (ko) | **75.53** | 73.42 | 74.52 | 73.88 |
| **MMLU** (en) | **83.83** | 82.07 | 82.37 | 82.88 |
| GSM8K (math) | 32.15¹ | **87.11** | 86.88 | 72.25 |
| **HumanEval** (code) | 62.20 | 20.73 | 11.59 | **68.29** |

¹ base GSM8K depressed by answer-format under strict-match.

**Tool-calling** (XML function-calling suite, non-thinking, temp 0):

| Metric | Base | **v1.2** |
|---|---:|---:|
| Single-turn (12 cases) | 11/12 | **12/12** |
| Multi-turn (call→result→answer) | ✅ | ✅ |
| Long-context tool call (~237k-token context) | — | ✅ |

**Verdict:** v1.2 is the **best Keural Nova overall** — best code (fixes the v1 collapse), best
tool-calling (incl. long context), best Korean MCQ/KoBEST, best MMLU of the fine-tunes.
**Honest trade-offs:** GSM8K lower than v1.0/v1.1 (still 2× base); small base-vs dips on
MMLU (−0.9) and HAE-RAE (−1.7) — the expected SFT knowledge trade-off. The eval gate flagged
these; release was a deliberate decision given the large code/tool/Korean gains.

## 6. Serving (vLLM)

```bash
python -m vllm.entrypoints.openai.api_server \
  --model mkd-hossain/Keural-Nova-v1.2-experimental \
  --served-model-name Keural-Nova-v1.2 \
  --tensor-parallel-size 2 --disable-custom-all-reduce \
  --max-model-len 262144 \
  --tool-call-parser qwen3_xml --enable-auto-tool-choice
```

- **Non-thinking default**; tool calls are **Qwen XML** (`--tool-call-parser qwen3_xml --enable-auto-tool-choice`).
- **Serve native 256K for agent/tool work.** 1M via YaRN is available but static YaRN degrades
  short-prompt tool-calling on Qwen models generally — enable it only for genuine >256K requests.

## 8. Limitations

Experimental — validate on your workload. GSM8K weaker than v1.0/v1.1; small MMLU/HAE-RAE dips
vs base; tool-calling at the full 1M-YaRN context not guaranteed (serving-side YaRN property).
Model weights are **not** in this repo (see the HF link); Apache-2.0, inheriting the Qwen base license.
